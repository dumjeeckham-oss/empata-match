# 동백 활동지원센터 매칭 프로그램 사용자 매뉴얼 및 데이터 가이드

문서 버전: 2026-08-25
대상: 이용자 관리, 활동지원사 관리, 상담, 매칭, 인계·인수 업무 담당자

이 문서는 프로그램을 처음 사용하는 실무자도 화면 구조, 데이터 입력 방법, 매칭 변경 절차, 대시보드 활용법을 한 번에 이해할 수 있도록 만든 통합 안내서입니다. 출력해서 보관하거나 앱의 [사용 매뉴얼] 메뉴에서 바로 확인할 수 있습니다.

---

## 1. 전체 화면 구성

### 1-1. 상단 메뉴

상단에는 주요 업무 메뉴가 가로로 배치됩니다.

- 대시보드: 센터 전체 현황을 요약해서 확인합니다.
- 이용자 관리: 이용자 등록, 수정, 계약 상태, 담당 활동지원사, 상담/매칭 이력을 관리합니다.
- 활동지원사 관리: 활동지원사 등록, 수정, 근무 상태, 담당 이용자, 상담/매칭 이력을 관리합니다.
- 매칭 관리: 이용자 조건과 활동지원사 조건을 비교해 추천 매칭을 확인합니다.
- 상담기록: 이용자 또는 활동지원사 상담 내역을 기록합니다.
- 종결확인서: 서비스 종결 관련 문서를 작성하고 관리합니다.
- 인계·인수서: 담당자 변경 시 필요한 인계·인수 내용을 작성합니다.
- 사용 매뉴얼: 현재 문서를 앱 안에서 확인합니다.

모바일에서는 메뉴가 접히는 방식이 아니라 가로 스크롤 탭으로 표시됩니다. 손가락으로 좌우로 밀어 원하는 메뉴를 선택하면 됩니다. 현재 선택된 메뉴는 색상과 밑줄로 강조됩니다.

### 1-2. 메인 대시보드

메인 대시보드는 센터 전체를 보는 종합 현황판입니다. 전체 이용자 수, 전체 활동지원사 수, 현재 매칭률 등 큰 흐름을 확인할 때 사용합니다.

---

## 2. 이용자 관리 화면 사용법

이용자 관리 화면은 좌우 2분할 구조입니다.

### 2-1. 좌측 영역: 전체 이용자 명단

좌측에는 검색창, 상태 필터, 이용자 카드 목록이 있습니다.

- 검색창: 이용자 이름, 연락처, 담당 활동지원사 이름/연락처로 검색할 수 있습니다.
- 상태 필터: 전체, 서비스중, 대기, 계약해지를 선택해 목록을 좁힐 수 있습니다.
- 이용자 카드: 이름, 성별, 나이, 연락처, 장애유형, 최초접수일, 담당지원사, 상태 뱃지를 표시합니다.
- 카드 클릭: 이용자 상세 정보 팝업이 열립니다.
- 연필 버튼: 이용자 수정 팝업이 열립니다.
- 삭제 버튼: 삭제 확인 창이 열립니다.

### 2-2. 우측 영역: 이용자 현황 요약 대시보드

우측 상단에는 최근 3개월 중심의 핵심 지표 카드가 있습니다.

- 3개월 신규 계약: 최근 3개월 안에 최초서비스제공일 또는 접수일이 있는 이용자 수입니다.
- 3개월 서비스 해지: 최근 3개월 안에 계약해지일이 있거나 계약해지 상태인 이용자 수입니다.
- 현재 대기자: 서비스 시작 전이거나 담당 활동지원사가 없는 이용자 수입니다.
- 인계/변경: 최근 3개월 안에 인계 또는 교체 관련 매칭 이력이 있는 건수입니다.
- 이용자 상담: 최근 3개월 안에 기록된 이용자/보호자 상담 건수입니다.
- 미처리 상담: 최근 상담 중 처리 결과가 없거나 미처리로 남은 건수입니다.

### 2-3. 우측 하단: 선택된 현황 상세 명단

요약 카드를 클릭하면 우측 하단에 조건에 맞는 명단이 바로 표시됩니다.

표시 컬럼은 다음과 같습니다.

- 이름
- 주요 일자: 계약일, 해지일, 상담일 등 해당 카드의 기준 날짜
- 상태 뱃지
- 비고/사유
- 상세 버튼

상세 버튼 또는 행을 클릭하면 해당 이용자의 상세 정보 팝업으로 이동합니다. 0건이면 “해당 조건에 해당하는 대상자가 없습니다.”라고 표시됩니다.

## 3. 활동지원사 관리 화면 사용법

활동지원사 관리 화면도 좌우 2분할 구조입니다.

### 3-1. 좌측 영역: 전체 활동지원사 명단

좌측에는 검색창, 상태 필터, 지원 가능 종류 필터, 활동지원사 카드 목록이 있습니다.

- 검색창: 활동지원사 이름, 연락처, 담당 이용자 이름/연락처로 검색할 수 있습니다.
- 상태 필터: 전체, 근무중, 대기, 퇴사로 목록을 좁힙니다.
- 지원 가능 종류 필터: 신체지원, 가사지원, 사회지원 등 가능 업무 기준으로 목록을 좁힙니다.
- 활동지원사 카드: 이름, 성별, 나이, 연락처, 경력, 지원가능 업무, 최초접수일, 담당이용자, 상태 뱃지를 표시합니다.
- 카드 클릭: 활동지원사 상세 정보 팝업이 열립니다.
- 연필 버튼: 활동지원사 수정 팝업이 열립니다.
- 삭제 버튼: 삭제 확인 창이 열립니다.

### 3-2. 우측 영역: 활동지원사 현황 요약 대시보드

우측 상단에는 활동지원사 기준의 핵심 지표 카드가 있습니다.

- 3개월 신규 입사: 최근 3개월 안에 최초근무일이 있는 활동지원사 수입니다.
- 3개월 퇴사: 최근 3개월 안에 퇴사일이 기록된 활동지원사 수입니다.
- 현재 근무 중: 현재 근무중 상태인 활동지원사 수입니다.
- 현재 대기: 현재 매칭 대기 중인 활동지원사 수입니다.
- 인계/변경: 최근 3개월 안에 담당 이용자 변경 또는 인계 이력이 있는 건수입니다.
- 상담/보고: 최근 3개월 안에 접수된 고충 상담, 현장 보고, 모니터링 기록 건수입니다.

### 3-3. 우측 하단: 조건별 상세 명단

요약 카드를 클릭하면 해당 활동지원사 명단이 즉시 표시됩니다.

예시:

- “3개월 퇴사” 클릭: 퇴사자 이름, 퇴사일, 상태, 퇴사 사유가 표시됩니다.
- “현재 대기” 클릭: 대기 중인 활동지원사 이름, 대기 기준일, 희망지역이 표시됩니다.
- “상담/보고” 클릭: 상담 또는 보고 대상자, 날짜, 상담 분류, 주요 내용이 표시됩니다.

행 또는 상세 버튼을 누르면 해당 활동지원사의 상세 정보 팝업으로 이동합니다.

## 4. 매칭 관리 화면 사용법

매칭 관리는 이용자 조건과 활동지원사 조건을 비교해 적합한 활동지원사를 추천하는 화면입니다.

### 4-1. 좌측 영역

좌측에서는 매칭할 이용자를 선택하고 활동지원사 후보 필터를 조정합니다.

- 이용자 검색: 대기 이용자 중 이름으로 검색합니다.
- 외국인만: 외국인 활동지원사만 후보로 봅니다.
- 주말가능: 토요일 또는 일요일 근무가 가능한 활동지원사만 봅니다.
- 업무별 가능 필터: 신체지원, 가사지원, 사회지원 등 필요한 지원 유형으로 후보를 좁힙니다.

### 4-2. 우측 영역

이용자를 선택하면 우측에서 이용자 정보, 상담 이력, 수동 매칭, 추천 결과를 확인할 수 있습니다.

매칭 점수는 다음 요소를 기준으로 계산됩니다.

- 시간 적합도
- 위치 근접도
- 이용자 선호 조건
- 활동지원사 거부 조건 또는 제한 조건

추천 결과에서 활동지원사를 클릭하면 상세 정보를 확인할 수 있습니다.

### 4-3. 매칭 성과 대시보드

매칭 관리 상단의 요약 카드를 클릭하면 성사된 매칭 쌍 또는 현재 대기 명단을 확인할 수 있습니다.

- 매칭 성공: 현재 서비스 중인 이용자-활동지원사 쌍과 매칭 성사일을 확인합니다.
- 매칭 대기: 매칭을 기다리는 이용자와 활동지원사를 함께 확인합니다.

## 5. 활동지원사 교체/종료 업무 절차

담당 활동지원사를 변경할 때는 기존 매칭을 먼저 정리해야 합니다. 이 절차는 1:다 중복 매칭을 예방하고 이력을 남기기 위한 핵심 절차입니다.

### 5-1. 기존 활동지원사 종료 후 신규 매칭

다음 상황에서 사용합니다.

- 기존 활동지원사가 서비스를 종료하고 다른 활동지원사가 새로 투입되는 경우
- 기존 활동지원사를 대기 또는 퇴사 상태로 변경해야 하는 경우

처리 순서:

1. 이용자 상세 또는 수정 화면에서 기존 활동지원사 옆의 서비스 종료/교체 기능을 선택합니다.
2. 서비스 종료일을 입력합니다. 날짜는 YYYY-MM-DD 형식입니다.
3. 종료 후 지원사 상태를 선택합니다.
   - 대기: 퇴사는 아니며, 다른 이용자와 다시 매칭 가능한 상태입니다.
   - 퇴사: 센터 근무가 종료된 상태입니다. 별도 퇴사일도 기록됩니다.
4. 저장하면 기존 활동지원사의 담당 이용자 연결이 해제됩니다.
5. 신규 활동지원사를 선택하고 서비스 시작일을 입력합니다.
6. 신규 활동지원사는 서비스 종료일이 비어 있으면 현재 서비스중 담당자로 표시됩니다.

결과:

- 이용자 상단 담당 활동지원사에는 현재 서비스중인 1명만 표시됩니다.
- 종료된 활동지원사는 하단 매칭 이력에서 확인합니다.
- 활동지원사 관리 화면에서도 기존 지원사는 대기 또는 퇴사로 바뀌고 담당 이용자 목록에서 제외됩니다.

### 5-2. 인계·인수 교체

다음 상황에서 사용합니다.

- 기존 활동지원사와 신규 활동지원사 사이에 인계 내용 기록이 필요한 경우
- 서비스 특이사항, 보호자 요청, 위험요소, 일정 등을 문서로 남겨야 하는 경우

처리 순서:

1. 담당 활동지원사를 교체하려고 하면 인계·인수서 작성 안내가 표시됩니다.
2. 인계·인수서 작성 화면으로 이동합니다.
3. 기존 지원사, 신규 지원사, 이용자, 인계 내용, 변경 사유를 작성합니다.
4. 인계·인수서가 저장되면 매칭 변경이 승인됩니다.
5. 변경 이력에는 사유가 인계 또는 교체로 기록됩니다.

### 5-3. 1:다 중복 매칭 경고가 뜨는 경우

한 이용자에게 현재 서비스중 활동지원사가 2명 이상이면 경고가 표시됩니다.

조치 방법:

1. 이용자 상세 화면에서 활동지원사별 서비스 기간 목록을 확인합니다.
2. 실제 현재 담당자 1명만 “현재 서비스 중”으로 유지합니다.
3. 나머지 활동지원사는 서비스 종료일을 입력합니다.
4. 종료된 활동지원사는 매칭 이력으로 이동합니다.
5. 필요하면 종료 후 상태를 대기 또는 퇴사로 정리합니다.

주의: 현재 담당 활동지원사는 원칙적으로 1명만 유지하는 것을 권장합니다. 예외적으로 복수 서비스가 실제 운영 정책에 맞는 경우에는 각 지원사의 기간과 사유를 명확히 기록해야 합니다.

## 6. 상담 기록 관리

상담기록 메뉴에서는 이용자, 보호자, 활동지원사 관련 상담 내용을 남길 수 있습니다.

권장 입력 항목:

- 상담일
- 대상 구분: 이용자 또는 활동지원사
- 대상자명
- 상담자명
- 상담 분류
- 상담 내용
- 처리 결과

대시보드의 상담 카드에는 최근 3개월 상담이 집계됩니다. 처리 결과가 비어 있거나 미처리로 남아 있으면 미처리 상담으로 볼 수 있습니다.

## 7. Firestore 데이터 구조 가이드

이 장은 실무자가 데이터 흐름을 이해하기 위한 설명입니다. 개발자용 필드명이 함께 적혀 있습니다.

### 7-1. users 컬렉션: 이용자 데이터

주요 필드:

- id: 문서 고유 ID
- name: 이용자 이름
- phone: 이용자 연락처
- gender: 성별
- txtUSex: 레거시 성별 필드. gender와 함께 유지됩니다.
- age: 나이
- disabilityType: 장애유형
- voucherTier: 바우처 구간
- requiredDays: 필요한 요일
- requiredHours: 필요한 시간
- supportTypes: 필요한 지원 종류 배열
- environmentTags: 환경 태그 배열
- address: 주소
- receiptDate: 최초접수일
- serviceStartDate: 최초서비스제공일 또는 서비스 시작일
- resignationDate: 계약해지일 또는 서비스 해지일
- contractStatus: 이용자 상태
- terminationReason: 중단/해지 사유
- txtUMemostop: 레거시 중단 사유 필드. terminationReason과 함께 유지됩니다.
- assignedHelperIds: 담당 활동지원사 ID 배열
- assigned_workers: 레거시/호환 담당 활동지원사 ID 배열
- assignedHelperNames: 담당 활동지원사 이름 배열
- assignedHelperPhones: 담당 활동지원사 연락처 배열
- matchingHistory: 문서 내부 매칭 이력 배열

이용자 상태 값:

- 서비스중: 최초서비스제공일이 있고 현재 담당 활동지원사가 있는 상태입니다.
- 대기: 최초서비스제공일이 없거나 현재 담당 활동지원사가 없는 상태입니다.
- 계약해지: 계약 또는 서비스가 종료된 상태입니다.
- 타기관 계약: 다른 기관과 계약한 상태입니다.
- 보류: 진행을 잠시 멈춘 상태입니다.

### 7-2. workers 컬렉션: 활동지원사 데이터

주요 필드:

- id: 문서 고유 ID
- name: 활동지원사 이름
- phone: 연락처
- gender: 성별
- txtHSex: 레거시 성별 필드. gender와 함께 유지됩니다.
- age: 나이
- residenceArea: 거주지역
- preferredArea: 희망 근무지역
- address: 주소
- experience: 경력 표시 값
- serviceStartDate: 최초근무일
- serviceEndDate: 특정 이용자와의 서비스 종료일 또는 매칭 종료 기준일
- retirementDate: 인사 기록용 퇴사일
- resignationDate: 레거시 퇴사일 필드
- contractStatus: 근무 상태
- supportTypes: 지원 가능한 업무 배열
- rejectionTypes: 거부 업무 배열
- availableDays: 근무 가능 요일
- availableHours: 근무 가능 시간
- assignedUserIds: 담당 이용자 ID 배열
- assigned_users: 레거시/호환 담당 이용자 ID 배열
- assignedUserNames: 담당 이용자 이름 배열
- assignedUserPhones: 담당 이용자 연락처 배열

활동지원사 상태 값:

- 근무중: 최초근무일이 있고 퇴사일이 없는 상태입니다.
- 대기: 현재 담당 이용자가 없고 매칭 가능한 상태입니다.
- 퇴사: 퇴사일 또는 retirementDate가 기록된 상태입니다.

### 7-3. matchingHistory 컬렉션 및 문서 내부 이력

매칭 이력은 별도 matchingHistory 컬렉션과 문서 내부 matchingHistory 배열 형태로 관리될 수 있습니다. 프로그램은 화면 조회와 상태 정리를 위해 두 구조를 함께 고려합니다.

주요 필드:

- type: 매칭, 해제, 시도 등 기록 유형
- userId: 이용자 ID
- userName: 이용자 이름
- userPhone: 이용자 연락처
- workerId: 활동지원사 ID
- workerName: 활동지원사 이름
- workerPhone: 활동지원사 연락처
- date: 서비스 시작일 또는 이력 발생일
- endDate: 서비스 종료일
- serviceStartDate: 서비스 시작일
- serviceEndDate: 서비스 종료일
- reason: 변경 사유. 교체, 추가, 종료, 인계 중 하나를 사용합니다.
- reasonDetail: 상세 사유. 필요 시 자유롭게 입력합니다.
- notes: 추가 메모

변경 사유 예시:

- 교체: 기존 담당자에서 새 담당자로 바뀐 경우
- 추가: 기존 담당자를 유지하면서 새 담당자가 추가된 경우
- 종료: 서비스 또는 매칭이 종료된 경우
- 인계: 인계·인수서 작성이 필요한 담당자 변경인 경우

## 8. 데이터 입력 원칙

### 8-1. 날짜 입력

날짜는 YYYY-MM-DD 형식으로 입력합니다.

예시:

- 2026-08-25
- 2026-09-01

이용자 최초서비스제공일을 입력하려면 최초접수일이 먼저 입력되어 있어야 합니다. 최초접수일이 비어 있으면 저장이 막히고 안내가 표시됩니다.

### 8-2. 담당자 배열 관리

이용자와 활동지원사는 서로 연결된 데이터입니다.

이용자에 활동지원사를 배정하면:

- 이용자 문서의 assignedHelperIds, assigned_workers가 갱신됩니다.
- 활동지원사 문서의 assignedUserIds, assigned_users도 함께 갱신됩니다.

활동지원사에서 이용자를 배정해도 같은 방식으로 반대편 데이터가 함께 갱신됩니다.

### 8-3. 기존 필드와 신규 필드 동시 유지

레거시 데이터 호환을 위해 일부 필드는 쌍으로 저장됩니다.

- 이용자 성별: gender, txtUSex
- 활동지원사 성별: gender, txtHSex
- 중단 사유: terminationReason, txtUMemostop
- 담당 활동지원사: assignedHelperIds, assigned_workers
- 담당 이용자: assignedUserIds, assigned_users

실무자는 화면에서 입력하면 되며, 프로그램이 필요한 호환 필드를 함께 저장합니다.

## 10. 상황별 실무 예시

### 경우 A. 활동지원사 교체/종료 발생

상황: 김동백 이용자의 기존 담당자인 박지원 활동지원사가 2026-08-31까지만 근무하고, 2026-09-01부터 이도움 활동지원사가 투입됩니다.

처리:

1. 이용자 관리에서 김동백을 검색합니다.
2. 상세 또는 수정 화면을 엽니다.
3. 박지원 옆의 서비스 종료/교체를 선택합니다.
4. 서비스 종료일에 2026-08-31을 입력합니다.
5. 종료 후 상태를 대기로 선택합니다. 실제 퇴사라면 퇴사를 선택합니다.
6. 신규 담당 활동지원사로 이도움을 선택합니다.
7. 서비스 시작일에 2026-09-01을 입력합니다.
8. 저장합니다.

확인:

- 김동백 상단 담당자는 이도움 1명만 표시됩니다.
- 박지원은 매칭 이력에서 종료된 담당자로 확인됩니다.
- 활동지원사 관리에서 박지원은 대기 또는 퇴사 상태로 표시됩니다.

### 경우 B. 대시보드 인터랙션 활용

상황: 최근 3개월 퇴사자를 빠르게 확인해야 합니다.

처리:

1. 활동지원사 관리 화면으로 이동합니다.
2. 오른쪽 상단 대시보드에서 “3개월 퇴사” 카드를 클릭합니다.
3. 오른쪽 하단 상세 명단에서 퇴사자 이름, 퇴사일, 상태, 사유를 확인합니다.
4. 특정 활동지원사의 상세 정보가 필요하면 해당 행 또는 상세 버튼을 클릭합니다.

### 경우 C. 매칭 성공 및 이력 관리

상황: 대기 이용자에게 적합한 활동지원사를 찾고, 매칭 이력을 남겨야 합니다.

처리:

1. 매칭 관리 화면으로 이동합니다.
2. 좌측에서 대기 이용자를 선택합니다.
3. 필요하면 외국인, 주말가능, 업무별 가능 필터를 조정합니다.
4. 우측 추천 결과에서 점수와 세부 조건을 확인합니다.
5. 실제 배정할 활동지원사를 이용자 관리 또는 활동지원사 관리에서 연결합니다.
6. 저장 후 매칭 이력에서 매칭 날짜와 담당자 정보를 확인합니다.

## 11. 자주 발생하는 문제와 확인 방법

### 11-1. 담당자가 여러 명으로 보일 때

원인:

- 과거 담당자의 서비스 종료일이 비어 있습니다.
- 현재 서비스중 체크가 2명 이상에게 남아 있습니다.

해결:

1. 이용자 상세 화면에서 활동지원사별 서비스 기간을 확인합니다.
2. 실제 현재 담당자만 서비스중으로 둡니다.
3. 과거 담당자에게 서비스 종료일을 입력합니다.
4. 종료 후 상태를 대기 또는 퇴사로 정리합니다.

### 11-2. 대기자가 너무 많이 보일 때

확인할 항목:

- 최초서비스제공일이 비어 있는지 확인합니다.
- 담당 활동지원사가 실제로 배정되어 있는지 확인합니다.
- 계약상태가 수동으로 대기 상태인지 확인합니다.

### 11-3. 활동지원사가 근무중으로 보이지 않을 때

확인할 항목:

- 최초근무일이 입력되어 있는지 확인합니다.
- 퇴사일 또는 retirementDate가 입력되어 있지 않은지 확인합니다.
- 담당 이용자 연결이 정상인지 확인합니다.

### 11-4. 스마트폰 화면에서 메뉴가 안 보일 때

상단 메뉴는 가로 스크롤 방식입니다. 메뉴 영역을 좌우로 밀어서 숨겨진 메뉴를 확인합니다.

## 12. 인쇄 및 보관 안내

이 문서는 인쇄 보관을 전제로 작성되었습니다.

권장 인쇄 설정:

- 용지: A4
- 방향: 세로
- 배율: 90% 또는 페이지에 맞춤
- 여백: 기본 또는 좁게
- 배경 그래픽: 필요 시 켬

앱 안의 사용 매뉴얼 화면에서는 인쇄 버튼을 눌러 바로 출력할 수 있습니다. 출력본은 신규 직원 교육, 업무 인수인계, 데이터 정리 기준 문서로 활용할 수 있습니다.
